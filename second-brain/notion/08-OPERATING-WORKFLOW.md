# 8 — Operating workflow

[← AI integration](07-AI-INTEGRATION.md) · [Backup and export →](09-BACKUP-AND-EXPORT.md)

## Daily — capture and continue

1. Use Quick Capture or the private form.
2. Write enough context to understand the item later.
3. Leave it in Inbox.
4. Do not stop current work to design the final page.

## Twice weekly — process Inbox

For each item:

1. Delete it if it has no future value.
2. Choose the Domain and Type.
3. Rewrite the title so search can find it.
4. Connect a Project or Source when relevant.
5. Set Sensitivity.
6. Move it to Active, Drafting, Done, or Archived.
7. Set a Review Date only when another review is meaningful.

Inbox is a temporary state, not a permanent filing cabinet.

## Weekly — review the system

- Process the remaining Inbox.
- Review active Projects and their Next Action.
- Check Sources to Verify.
- Move content through its pipeline.
- Review every AI Status = Needs Review item.
- Find projects without supporting knowledge.
- Create the next Weekly Review page.
- Record one focus for the coming week.

## Monthly — maintain structure

- Merge duplicate Topics.
- Archive inactive domains only after reviewing their content.
- Find stale projects and notes.
- Review connected integrations and permissions.
- Export the workspace or relevant pages.
- Open and inspect the export.

## Adding a domain later

1. Add it to Domains.
2. Set its sensitivity and AI policy.
3. Add a filtered Knowledge view to HQ.
4. Add it to relevant dashboard charts.
5. Create a domain-specific template only if its page structure is genuinely
   different.
6. Rerun the local planner if you want the saved plan to match.

## Migration from Obsidian

Treat migration as a separate reviewed project:

1. Start with active notes, not the entire archive.
2. Preserve the original vault as a read-only fallback.
3. Import a small sample.
4. Check properties, attachments, links, code blocks, and dates.
5. Decide how Obsidian wiki links map to Notion relations.
6. Continue in batches only after the sample is correct.

Never delete the Obsidian source merely because an import completed.
