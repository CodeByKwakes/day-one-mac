# Optional 11: generate MCP connection snippets

Generate reviewed HTTPS configuration artifacts for selected clients after
the required client and runtime tools. Model Context Protocol (MCP) connects an AI client to tools or data.
The generator does not start a server, connect an account or approve access.

## Before you start

Choose at least one installed AI client, review the endpoint and decide project
scope. Use [direct manual setup](../../setup/manual/ai/mcp.md) for local stdio servers,
user/global scope and other clients. Use [Docker MCP](../../setup/manual/ai/mcp-docker.md)
for the Docker gateway; it is not an HTTPS manifest row.

## Executable workspace-snippet route

After checking prerequisites, Module 11 can generate private configuration snippets for Claude
Code, Codex and VS Code. It does **not** connect to servers, read tokens, launch
clients, edit live configuration or approve trust. Other clients, local stdio
commands and user/global scope use the [manual MCP guide](../../setup/manual/ai/mcp.md). Docker
profiles and gateway launchers use the linked Docker guide; do not put a
`docker` command or `docker://` reference into this five-field HTTPS manifest.

Create a new manifest with your editor. Use five **tab-separated** fields per
row: client, server name, scope, HTTPS endpoint and token environment-variable
name (or `-`). This demonstration endpoint is not a working server:

```text
codex	example	workspace	https://mcp.example.com/mcp	DAY_ONE_MCP_EXAMPLE
claude	example	workspace	https://mcp.example.com/mcp	DAY_ONE_MCP_EXAMPLE
vscode	example	workspace	https://mcp.example.com/mcp	DAY_ONE_MCP_EXAMPLE
```

Save only the client rows you need as `mcp.tsv`, replace the endpoint with one
you have reviewed, and run:

```bash
day-one-mac tool --module 11 --plan --manifest ./mcp.tsv
day-one-mac tool --module 11 --apply --manifest ./mcp.tsv
day-one-mac tool --module 11 --check
```

Read the files at the printed artifact path. Before activating anything, back
up the destination file and merge just the reviewed server entry:

| Generated file | Workspace destination | Activation boundary |
|---|---|---|
| `claude-mcp.json` | `.mcp.json` | Keep project/server approval prompts enabled |
| `codex-mcp.toml` | `.codex/config.toml` | Entries have `enabled = false`; enable deliberately after review |
| `vscode-mcp.json` | `.vscode/mcp.json` | Review server trust and tool approval in VS Code |

These destinations use the documented [Claude MCP schema](https://code.claude.com/docs/en/mcp),
[Codex MCP schema](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
and [VS Code MCP configuration](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).
Never overwrite an existing configuration with a whole generated file.

The generated VS Code file uses its compatibility `servers` format. For a new
portable Copilot configuration, follow the [manual VS Code recipe](../../setup/manual/ai/mcp.md) instead. Do not rename this
file to `.mcp.json`: that destination requires a `mcpServers` wrapper, and
credential variable syntax must be checked for every client that reads it.

The dedicated `DAY_ONE_MCP_` name is a placeholder, not a secret value.
Supply the actual token securely to the intended client's environment yourself;
GUI apps do not necessarily inherit terminal environment variables. A `-`
omits the token header; it does not configure OAuth or establish that the server
is unauthenticated. Complete provider-specific authentication manually.

URLs cannot contain embedded credentials, query strings or fragments. Check
the hostname and path too: a token hidden in a path is still a secret and must
not be included. `--check` verifies generated bytes and saved choices, not
connectivity. `--resume` generates a new version from saved choices without
rereading `mcp.tsv`. Finish the harmless connection test in the manual checklist.

## Verify and recover

Run the generated-byte check shown above. Expected result: saved choices and
artifacts match. Then complete the selected client's manual trust/authentication
step and a harmless request in the [manual MCP guide](../../setup/manual/ai/mcp.md).
Return here only after the actual client reports the expected tool access.

If the manifest is rejected, check its five tab-separated fields and the HTTPS
endpoint restrictions. If a client cannot connect, inspect its scope, executable
or environment and authentication separately. Restore the previous client entry
to undo activation; removing an artifact does not revoke an external token.
